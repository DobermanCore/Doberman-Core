- **Policy as code.** A repo-committed `doberman.policy.yaml` (`blocked:` / `sensitive:` glob lists) is now resolved
  through the `PolicySource` seam on every action, so teams can review policy in pull requests. Additions apply
  immediately; dropping a glob is held by a pinned snapshot in `.doberman/` until `doberman policy-file --accept` passes
  the same confirm-plus-possession-factor gate as `doberman mode`. A malformed or unreadable file never loosens anything.
  Registered `doberman.policy_sources` plugins now actually reach the decision path (the seam was dormant), and a plugin
  whose `snapshot()` raises is logged and skipped. (#147)
- **`doberman memory seed --from traces.jsonl`** warms the per-entity behavioural baseline from operator-supplied
  allowed-action traces through the production `observe()` path, so a fresh install is not cold on day one. Any
  non-`PASS` or malformed row refuses the whole file; targets must be repo-relative classes; the summary carries counts
  and a 12-character entity prefix only. The in-process anomaly forest is not persisted and is reported as such.
  Format and invariants in `docs/BASELINE_SEEDING.md`. (#326)
- **`whole_script_confusable`** joins the Unicode-smuggling channels: a token written entirely in Latin-lookalike
  Cyrillic or Greek letters (an all-Cyrillic "paypal") is a soft signal that steps the action up to `AUTH`, with corpus
  rows under the ASR/FPR gate. The channel stays silent when the same text carries genuine Cyrillic or Greek, so
  Russian or Greek prose in a commit message or file is not flagged. (#141)
- **Cost observers can receive loop anomalies.** A `doberman.cost_observers` plugin may implement an optional
  `on_loop_anomaly(anomaly)`; the loop detector now runs after each tool-call cost event when an observer is installed.
  (#143)
- **A worked detector plugin** at `examples/plugin-detector/`, plus `docs/EXTENDING.md` listing all twelve entry-point
  groups and the defensive-loading guarantee. (#200)
- **`docs/CONTROL_COVERAGE.md`** maps Doberman's controls to the OWASP Top 10 for LLM Applications (2025) and the NIST
  AI RMF, stating plainly what is covered, partial, or not addressed. (#248)
