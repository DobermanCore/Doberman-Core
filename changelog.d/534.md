- **`doberman tui` is now a real decision browser.** Columns are reordered (verdict, time, risk,
  auth, action, target, why) with an ASCII verdict glyph (`X BLOCK` / `! AUTH` / `. PASS`) rendered as
  a high-contrast chip for BLOCK/AUTH (bold black on a solid color, meeting a 4.5:1 contrast floor
  including under the cursor); risk severity and the auth outcome are colored and humanized too
  ("blocked", "ran", "confirmed (memory)" - same wording `doberman log` now also uses). A one-line
  glyph legend sits in the date bar. The table and the "why" panel each get a visible border when
  focused (`tab` to move focus), and Home/End always jump to the first/last row no matter which one
  has focus. `enter`/`w` opens a full-screen, modal why view with every reason code, the action id, and
  a "Next" line naming the real command that would change this decision (`doberman mode`, `doberman
  review --yes`, `doberman dash`'s approval queue) - `b`/`B`/`a` keep working inside it to page through
  BLOCK/AUTH rows without closing it. The panel says whether it's showing the offline template or an
  LLM narration (and now never gets stuck on "narrating..." if the LLM call itself raises). New
  bindings: `?` help, `/` filter (verdict/target/action/reason codes), `b`/`B` next/previous BLOCK
  (notifies when none match), `a` next AUTH, `y` copy the action id (toast now says clipboard is via
  terminal OSC 52), `home`/`end`; the footer is ordered by importance so it still reads useful bindings
  at 80 columns. `--last` (default 500, minimum 1, mirrors `doberman log --last`) bounds the load and
  the header shows "showing N of M - path" (count first, so it survives truncation); a missing decision
  log (path shortened with `~`), an empty one (now with two concrete next steps: trigger a real tool
  call, or run `doberman demo --fast`), and a bad `--path` (nonexistent, or a file instead of a
  directory - both exit code 2) each get their own honest message instead of one generic placeholder.
  A third pass: a 1-char ASCII gutter (`>`) marks the cursor row so selection reads without relying on
  color; the "Next" step is now docked in its own line under the why panel so it never scrolls out of
  view; the full-screen why opens with a one-line header (verdict, time, risk, action, target) so
  paging through rows with `b`/`B`/`a` never loses track of which row is on screen, and that footer
  now shows `b`/`B`/`a` too; `showing N of M` says `(last N; --last for more)` when the load hit the
  `--last` cap; a log spanning more than one calendar day shows `MM-DD HH:MM` instead of `HH:MM:SS`;
  the "why" column now reads as words (a short label, or the reason code with underscores turned to
  spaces) instead of raw codes, while the panel/full-screen why keep the raw codes; `/`'s filter now
  has a documented exit (`enter` keeps it and returns focus to the table) as well as a reset (`escape`
  clears it from the table too, not just the filter box); and `doberman log`'s "approved via 5-minute
  memory (soft_confirm)" wording is unchanged, with the `tui`'s narrow auth column showing a short
  "memory ok" instead.
  A fourth pass: the docked "Next" line no longer clips - it wraps onto up to 3 lines instead of a
  fixed 1, and the BLOCK/AUTH remedy text leads with the actual commands so nothing gets lost; the
  `why` column now keeps at least 8 columns at 80 terminal columns on single- and multi-day logs alike
  (the room comes from `auth` - "mem ok" replaces "memory ok" - `action`, and `target`, never from
  `why`); `why`/copy id/next-prev-BLOCK/next-AUTH are hidden footer entries (not dead keys) whenever no
  row is visible, and the empty-filter message now says to press esc to clear it; `y` (copy id) also
  works from inside the full-screen why screen and appears in its footer too; risk severity is now a
  full gradient - critical/high/medium are each a distinct high-contrast chip (medium's plain
  foreground text measured only 4.06:1 under the cursor row); `doberman.explain`'s offline template
  leads with a plain "Doberman decided VERDICT after checking the rules[ and the behaviour baseline]"
  summary (the more technical "<layer> decided <verdict>" phrasing moves to a trailing technical
  detail rather than being dropped); the help screen is grouped into Navigate/Find/Read/App so nothing
  wraps at 80 columns; the copy toast drops the "OSC 52" jargon for an honest "your terminal decides
  whether it lands"; and `doberman log` gains `--why`, which prints that same one-line summary plus the
  same "Next" step under each BLOCK/AUTH row (default output and `--jsonl` unchanged).
  A fifth pass: the full-screen why no longer repeats "press w for detail" (it IS the detail; the docked
  `#next-line` and `doberman log --why` are unaffected); the footer drops `B`/`a`/`y`/`r` below 100
  columns so the rest never wraps or gets silently clipped - they stay fully live via the keyboard and
  documented in `?`; `target` is now a fixed 6-wide column (never grows) so `why` gets the room it used
  to share, and when every loaded row's target is "-" (true of any shell_exec row) the column drops out
  of the table entirely, handing `why` even more space; `?` is a real modal now - it never stacks a
  second help screen and `w`/`b`/`B`/`a` are inert while it's open; the help body scrolls with a
  "(scroll for more)" cue only when it actually overflows the terminal; the docked/full-screen why panel
  now leads with the explanation and ends with a muted, dimmed provenance line instead of the reverse,
  and the "Next" line's own "Next" prefix renders bold in the AUTH accent color so it reads as the
  remedy; a pending AUTH row (no answer yet) shows "pending" (`tui`) / "pending - not yet answered"
  (`doberman log`) instead of a bare "-", which was indistinguishable from "never had an auth step at
  all"; the focused pane's border now also gets a `[focus]` title, not just a color change; with zero
  rows loaded the date-bar legend and the `/` filter footer entry disappear too (there is nothing to
  filter); and below 76x12 the app shows one line ("Terminal too small - resize to at least 76x12")
  instead of a broken layout. Also: a quoted `'doberman <command>'` phrase in a "Next"/`--why` line no
  longer breaks across two wrapped lines on a narrower terminal.
  A sixth pass: the table's width budget now reserves a column for Textual's own vertical scrollbar (it
  is 2 columns wide, not 1) and the table also sets `overflow-x: hidden` as a second, unconditional
  guarantee - no spurious horizontal scrollbar at 80 columns even with more rows loaded than fit;
  `b`/`B`/`a`/`home`/`end` now explicitly scroll the cursor row into view; below 76x16 (raised from
  76x12, so the docked why panel keeps room for at least 3 lines) the app shows the one-line notice
  instead of a broken layout; the header now shows a verdict breakdown over the loaded rows
  ("showing N of M - 22 BLOCK / 1 AUTH / 22 PASS - path"); on a fresh load the cursor starts on the
  newest BLOCK/AUTH row instead of row 0 when one exists (`home` still goes to row 0); the help
  screen's "(scroll for more)" cue is now the FIRST line when the body overflows, not only appended at
  the bottom after already scrolling past everything; the date-bar legend now renders at the normal
  text color (only the date itself is muted) so the glyph legend stays readable; the footer hides
  "/ filter" while the filter input has focus (pressing `/` there just types a literal slash) and shows
  a synthetic "enter keep" affordance instead; `doberman.explain`'s trailing technical aside changes
  from "(Decided by: the objective [and subjective] guardrail layer[s together].)" to "(Checked by: the
  rules[ and the behaviour baseline].)"; `doberman log --why` now prints the "what was attempted" and
  "Reasons: ..." sentences (the actual new information), not just the one-line verdict summary the row
  above already implied; and the missing-decision-log message now names the real first step -
  "Run 'doberman setup' here to start guarding this repo."
  A seventh pass: `target` is no longer pinned at a fixed 6 columns - it now claims spare width up to
  its content need (capped at 24, floored at 8) BEFORE `why` absorbs whatever's left, so a real value
  like "backend/secrets/*.env" is actually readable instead of unreadable at 3; `_truncate` never shows
  a bare cut with no "..." marker either. The `time` column and date bar now show your LOCAL time/date
  (marked "(local)"); the why panel and full-screen why show the row's absolute UTC instant plus a
  relative age ("2026-09-02 09:31:05 UTC (2m ago)") instead. A docked/full-screen why body that
  overflows its space now gets a muted "(scroll for more)" cue, same as the help screen. The footer is
  simplified to a fixed 6 bindings (`w`/`/`/`b`/`?`/`q`/`r`) at every width, never more - `B`/`a`/`y` are
  keyboard-only now (documented in `?`), and `next AUTH` is a genuine no-op (not a "no AUTH rows in
  view" notify) when the loaded window has no AUTH row at all; the too-small notice's footer now shows
  only `q`/"quit" (every other key still works, just hidden). `?` now opens from inside the full-screen
  why view too (escape returns to it). And `doberman log --why` over a window with no BLOCK/AUTH row
  prints "(no BLOCK or AUTH rows in this window - nothing to explain)" instead of silently adding
  nothing.
  An eighth pass: the docked why panel's absolute-time+age line (and the `[focus]` cue) moves out of
  the panel body and into its border title, and the "(scroll for more)" cue moves into its border
  subtitle - at 80x24 the body used to show only the cue and the timestamp, pushing the explanation
  itself below the fold; now the body always starts with the explanation (at least 5 lines visible at
  80x24, at least 3 at 76x16), and below ~30 terminal rows the panel gets the larger share of the split
  instead of the table (which keeps a floor of 6 visible rows either way). `risk` and `auth` now drop
  out of the table below 100 terminal columns - both are already restated in the why panel/full-screen
  why - handing that width to `target`/`why` (each guaranteed at least 12 columns at 80 with real data);
  `target`'s own floor now shrinks below its old fixed 8 when every loaded value is genuinely short
  (".env", or missing), donating the rest to `why` instead of padding a column nothing needs. The
  header now reads "showing N of M (filtered) - X BLOCK / Y AUTH / Z PASS loaded" so it's clear which
  count is filtered and which is the loaded total. `?` now also lists the arrow keys and page up/down
  (DataTable's own built-in bindings). `b`/`B`/`a` on the only matching row in view (cursor already on
  it) now says "no other ... rows in view" instead of silently "jumping" to the same row. An empty log,
  a filtered-to-zero view, and a missing decision log now replace the table itself with the message (in
  the table's own area), instead of showing it in the why panel below an empty table. And `doberman log`'s
  plain timestamp column now reads "YYYY-MM-DD HH:MM:SS UTC" (no microseconds), the same format the tui's
  why panel uses - `--jsonl` keeps the raw stored value unchanged.
