- **The auth dialog names the target, the risk, and the deadline clearly, and never hides the
  question.** The target/command sits in its own bold, high-contrast panel, capped at 6 lines with a
  middle-ellipsis preview (rendered in a muted color so it can never be mistaken for real target text)
  and a "Show all N characters"/"Show less" toggle for a very long or many-line target, which expands
  into a scrollable region capped at 70% of the monitor's work area — the question, risk line, and
  countdown are drawn outside that panel so they can never be pushed out of view, and the dialog is
  centered and clamped inside the monitor's work area (never the taskbar-covered full monitor rect) so
  the buttons can never end up off-screen. The countdown ticks live ("auto-denies in 1:59"), adopts the
  same amber/red severity ramp as the risk line as time runs low (bold BLOCK-red under 10s), and shows
  "Denied - no answer in 2:00" before closing — expiry now resolves the answer to a denial, disables
  both buttons and the code entry, and unbinds Return/Escape/Ctrl+Enter the INSTANT the countdown hits
  zero (not 1.5s later, when the flash finishes), so a click or keypress landing during the flash can
  never turn a denial back into an approval. Deny is the solid/primary button and Approve is
  outlined/secondary (the fail-closed default reads as the dominant one); both are real, accessible
  `ttk.Button`s (44px+ tall) with Tab/Left/Right cycling between them, Return invoking only whichever one
  is actually focused, and Ctrl+Enter acting as a deliberate APPROVE-only accelerator (a no-op unless
  Approve already holds focus — it is not a second way to deny). The keyboard focus ring itself now
  clears WCAG 1.4.11's 3:1 non-text-contrast bar against both buttons (it previously measured only
  ~1.6–2.1:1; no light color could reach 3:1 against the tan Deny fill, so the ring moved to a dark,
  still visually distinct hue). The target stays keyboard- and screen-reader-reachable (state stays
  "normal", never "disabled", with bindings that block edits instead) and shows a best-effort taskbar
  flash + system bell on open. The one-time-code entry now shows a label above the field, is 8 chars
  wide, strips a pasted separator ("123 456" → "123456"), and shows an inline error that names the
  EXACT problem ("Codes are 6 digits - you entered 4." / "Only digits, please.") instead of repeating
  the prompt — Enter and Ctrl+Enter in the entry both submit. A short line under the question — "Denying
  stops only this action; your agent keeps running." — states what a Deny actually does. Best-effort
  per-monitor-v2 DPI awareness (falling back to the older system-DPI call on older Windows) scales to
  the DPI of the monitor the dialog is actually placed on, including body-text wrap widths.
- **The auth dialog states risk severity, the agent's identity, and never duplicates itself.** Risk now
  renders as a small filled severity chip ("HIGH"/"MEDIUM"/"LOW") plus bold BLOCK-red (critical/high),
  amber (medium), or plain body text (low) — always alongside the word itself, so meaning never rests on
  color alone. An "Agent: `<role>` - via `<tool>`" line appears under the headline when known. The
  "technical" tone (which already embeds its risk badge in the headline) no longer draws a second,
  duplicate risk line — a compact "Action: `<verb>`" line takes its place instead, so the acted-on verb
  (missing from the structured technical rendering before) is visible again. Every dialog outcome
  (approved/denied/expired) now logs exactly one INFO line naming the action id — never the target.
- **The auth dialog's focus ring is now visible on BOTH buttons, in every tone, and a human can ask
  for more time.** The keyboard focus ring is two-tone (an inner line against each button's own fill,
  an outer line against the window background) because no single flat color could clear WCAG 1.4.11's
  3:1 non-text-contrast bar against Deny's tan fill AND Approve's near-black fill AND the window
  background at once — the round-2 fix had only been measured against Approve's amber TEXT color, not
  its actual panel-colored fill, where it measured 1.25:1. The severity chip now renders in every tone
  (previously suppressed for "technical"), the second (code-entry) dialog of a two-factor flow now
  states the reason, the reassurance line, and "Step 2 of 2" just like the first, and a "More time
  (+2:00)" control (usable once, never the default focus, logged when used) satisfies WCAG 2.2.1. A
  long target now collapses by whole LINES (first 4 + an ellipsis + the last) instead of a
  character-offset cut that could slice through the middle of a token and hide part of it with no
  indication; a single unbroken line (e.g. a long URL) is never sliced at all, only visually clipped by
  the height cap. The brand block shrinks to under 48px so the freed space becomes a hairline divider
  between the "what" and "decide" groups, the severity chip's font meets the file's own 9pt floor, the
  "Show all N characters" toggle is now "Show the full command", and the window title drops its em
  dash for a plain hyphen (ASCII/cp1252-safe, like every other string here). A prompter can now
  implement `notify_outcome(parts, outcome)` (getattr-gated, never raises) so a wrong-but-well-formed
  code no longer just silently closes the window — the GUI shows a small, non-focus-stealing "Code
  rejected" / "Approved" / "Denied" notice for ~1.2s. `TtyPrompter` gained its own `timeout_s`
  (symmetric with `GuiPrompter`'s), so the deadline note it prints is always its own real, constructed
  value rather than a disconnected module default. Also fixed: the DPI-awareness tests crashed on
  non-Windows CI because `ctypes.windll` doesn't exist there; `_enable_dpi_awareness` now guards with
  `getattr`.
- **The human-tone auth challenge states risk, not just the target and reason.** `doberman.auth.provider`
  gains a `challenge_parts()` seam that builds the structured facts behind a challenge (target, why,
  risk, tier, role, tool, action id, ...) once and renders both tones from it, so the plain "human" tone
  now includes a line like "Risk: high - this needs your code" alongside the exact target. A `Prompter`
  can optionally implement `confirm_challenge(parts)` / `read_code_challenge(parts)` to receive these
  tagged facts directly (the GUI does); every existing `confirm(message)`/`read_code(message)`
  prompter — TTY, dashboard, a plugin — keeps working unchanged via the flattened string.
- **The auth dialog's focus ring now actually paints, LOW severity reads as the least alarming chip,
  and CRITICAL gets a deliberate-gesture pause.** A pixel probe found the outer ring line never
  rendering on some Tk builds because the wrapper frame's `highlightcolor` was never set (only
  `highlightbackground`) — both are now set together, verified with a real screen-pixel probe (not just
  `cget()`) on both Deny and Approve. The LOW severity chip is now a muted OUTLINE (no fill) instead of a
  near-white filled block — the least alarming severity could previously read as the single brightest
  element on the dialog. CRITICAL additionally colors the headline text itself and holds Approve
  disabled for 1.5s with a live "Approve (2)"-style countdown on the button label — an escalation
  strictly above what HIGH already requires. A single-line target that overflows the 6-line cap now
  shows a muted "... (N more characters)" marker instead of a silent visual clip, and the "Show the
  full ..." toggle names the actual noun (command/path/URL) derived from the action instead of always
  saying "command". The post-decision outcome notice is now differentiated (amber for Approved, the
  same BLOCK-red the risk chip uses for Denied/Code rejected, with a one-line next step for a rejected
  code) and carries the brand mark + wordmark so it reads as recognisably Doberman. Inside the dialog,
  the agent-identity/why/risk/reassurance lines are grouped together with a hairline above the risk row,
  the why line is promoted to body face/color (it must outrank the keyboard hint, not match it), and the
  approval-memory notice moves to after the target panel ("read after the action") styled as a muted
  note instead of a brand-colored alert shown before the human even sees the target. Inline code-entry
  errors and the countdown's expiry flash now use the same BLOCK-red the risk chip uses, not Approve's
  amber. A collapsed-by-default "What is this?" link expands a two-line plain-language explanation of
  what Doberman is and why this action stopped. The terminal's second (code-entry) step now names the
  exact target ("Enter your 2FA code to approve: <target>"), keeping the action binding the first step
  already established; the GUI's live countdown and the CLI's static note now share one `render.py`
  template so the wording can never silently drift between channels. Technical tone no longer repeats
  "HIGH" between the headline bracket and the severity chip — the chip alone carries it now, alongside
  the risk sentence itself.
