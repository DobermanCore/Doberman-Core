- **Command-walk hardening.** `DestructiveCommandRule` sees through shell syntax (`if`/`then`/`do`/`{`/`(`/`!`,
  `function NAME`, `coproc [NAME] {`), transparent wrappers with a fixed option table (`sudo -u`, `env -i`/`-S`,
  `nice -n`, `timeout N`, `doas`, `runuser`, `chroot`, `nohup`, `stdbuf`, …; `su -c` is opaque like `bash -c`),
  and nested command substitutions; process kills (`kill`/`pkill`/`killall`/`taskkill`/`Stop-Process`, `os.kill`,
  psutil, `process.kill`) are AUTH; an interpreter one-liner that spawns a subprocess is AUTH `opaque_command` and
  its literal command lines are walked; a package-manager verb reached only through wrapper options or an inline
  `HOME=`/`*_CONFIG*=` assignment no longer qualifies for the implied-registry PASS. Every scan bound (segments,
  spawn literals, substitution depth, candidate count, filesystem resolves) is a floor that fails upward to AUTH,
  never a skip; `names_control_plane` matches every path textually and resolves through the filesystem only for
  absolute/`~`/`..` tokens (a relative on-disk symlink into the control plane is no longer followed by the command
  rule — the file-target path rule remains the backstop) (#580)
